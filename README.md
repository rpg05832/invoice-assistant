# חשבונית · Invoice Assistant

כלי מקומי בעברית למנהלי חשבונות, עם FastAPI, SQLite וממשק דפדפן ב־RTL. גרסה ראשונה **0.1.0 לבדיקת עבודה**, לפי [האפיון המקורי](docs/specification.html).

## התקנה ב־Windows

1. הורידו את המאגר כ־ZIP וחלצו לתיקייה קבועה שבבעלותכם, למשל `C:\InvoiceAssistant`. אל תפעילו מתוך ה־ZIP, תיקיית Program Files או תיקיית סנכרון משותפת.
2. התקינו Python ‏3.12–3.14 עם Python Launcher.
3. התקינו Tesseract 5. אפשר ב־Terminal: `winget install --id UB-Mannheim.TesseractOCR --exact`.
4. לחצו פעמיים על `setup.cmd`. ההתקנה הראשונה דורשת אינטרנט: היא מתקינה תלויות ומורידה מודלים רשמיים בעברית ובאנגלית, עם אימות SHA‑256.
5. לחצו פעמיים על `start.cmd`. הדפדפן ייפתח בכתובת המקומית `http://127.0.0.1:8765`. השאירו את חלון השרת פתוח בזמן העבודה.

לאחר ההתקנה, העבודה אינה דורשת ענן או חיבור לאינטרנט. Python ו־Tesseract הם דרישות מוקדמות; זו אינה עדיין התקנת EXE עצמאית. המערכת מיועדת למשתמש אחד במחשב אחד.

## מה עובד בגרסה הזו

- כמה חברות עם אינדקסים, התאמות ופרופילי יצוא נפרדים.
- יבוא ספקים מ־XLSX/CSV/TXT: בחירת גיליון ומיפוי, בדיקת שורות ושינויים לפני שמירה, ושימור קודי כרטיס עם אפסים מובילים. היבוא אטומי ושומר מזהי כרטיס והתאמות קיימות.
- העלאת PDF, JPG, PNG ו־TIFF (גם WebP), עד 25MB ו־50 עמודים לקובץ. קריאת טקסט מ־PDF או OCR מקומי לעברית ולאנגלית. כל עמוד מתחיל כמסמך נפרד.
- פיצול ידני של כמה חשבוניות באותו דף, סיבוב חיתוך וקישור למקור. אפשר לנקות ולצייר מסגרות מחדש לפני אישור.
- סימון מספר צ׳ק בעמוד המקורי, גם בשוליים מחוץ לחשבונית המפוצלת; OCR ממוקד, הגדלת המקור, תיקון ידני וכמה צ׳קים למסמך. המספרים נשמרים כטקסט ואישורם נדרש לפני יצוא. אותו מספר יכול להופיע בכמה חשבוניות.
- תיקון לצד המקור, התאמה לספק לפי מספר עוסק או כינוי מאושר, שמירת כינויים בחברה, בדיקות חובה/סכומים/זיכוי/חברה מקבלת וספק פעיל.
- חסימת קובץ זהה בחברה וחשד לכפילות לפי ספק (גם כרטיסים שונים עם אותו מספר עוסק), סוג ומספר מסמך. ארכוב מסמך כפול לפני אישור.
- תצוגה מקדימה של יצוא, עמודות/אורכים/תאריך/קידוד ניתנים להגדרה, CSV ו־Excel, ומנות שמורות. גיליון הצ׳קים שומר אפסים מובילים. תאי טקסט מוגנים מהפעלה כנוסחאות.
- מצב ״יוצא״ נפרד מ״נקלט״. אישור או דחייה ידניים מחייבים סיבה; רק מסמך שנדחה ניתן לתקן ולהעביר למנה חדשה. המנה הקודמת נשמרת כפי שנוצרה.
- יבוא והשוואה של תעודות משלוח לפי קוד ספק ואסמכתא, היסטוריית שינויים, גיבוי ושחזור לתיקייה חדשה.

## מגבלות שצריך להכיר

**בחירת תוכנת יעד אינה יוצרת מחבר ואינה מאמתת קליטה.** כל היעדים מסומנים כלא מאומתים. Excel/CSV זמינים כברירת מחדל. פרופיל באורך קבוע וקבצי פרמטרים נלווים מאפשרים מימוש מפרט מתועד; אין תבנית MOVEIN/מבנה אחיד/DTW שמסומנת כמאומתת מראש. API פועל רק לפי כתובת ומיפוי שהוגדרו ואישור שליחה מפורש. תנועת תשלום ליצוא מחייבת הזנה ואישור נפרדים, ואינה מבצעת תשלום בבנק.

Tesseract אינו מודל ייעודי לכתב יד. תוצאה יכולה להיות שגויה או ריקה; יש לבדוק מול התמונה, לתקן ולאשר. בוצע ניסוי קטן בדוגמה אמיתית; הוא חשף טעויות במספרי צ׳קים ואינו מדידת דיוק מייצגת. זמן עבודה במחשב Windows של המשתמש טרם נמדד. בחירת המודלים מבוססת על חומרת סביבת הבדיקה, לא על בדיקה של המחשב שלכם.

הגרסה הורחבה גם להצעת פיצול, הזזה ושינוי גודל של מסגרות, חיבור ופירוק עמודי המשך, תיקון הטיה וניגודיות, אזורי מקור לשדות שאותרו, יבוא לקוחות/עובדים/חשבונות ורשימות נוספות, כללי רישום לספק וסוג מסמך, שורות פריטים עם בדיקת סיכום, ופקודת יומן מאוזנת. זמינים פרופיל טקסט באורך קבוע, קבצי פרמטרים נלווים לפי מפרט הלקוח, חבילת קליטה, דוח תוצאות יבוא ו־API במיפוי מפורש. חיבורי OpenAI, Claude, Gemini, Mistral OCR ו־Google Document AI ניתנים להגדרה לפי חברה ופעולה, עם תקרת תקציב מקומית והצעות לאישור. המפתחות וההתקנות החיצוניות עדיין נדרשים לבדיקה חיה; המערכת לא טוענת שאומתו. פירוט ראיות ומגבלות מופיע בדוח האימות.

## גיבוי ושחזור

בהגדרות בחרו ״הורדת גיבוי ZIP״. הגיבוי כולל מסד נתונים עקבי, קבצי מקור, תמונות עמודים וחיתוכים. המודלים והתוכנה מותקנים בנפרד. שמרו עותק מחוץ למחשב.

לשחזור, עצרו את השרת וב־Terminal בתיקיית התוכנה הריצו:

```bat
.venv\Scripts\python.exe scripts\restore_backup.py C:\Backups\backup.zip C:\InvoiceAssistant\restored-data
set "INVOICE_DATA_DIR=C:\InvoiceAssistant\restored-data"
.venv\Scripts\python.exe run.py
```

תיקיית היעד חייבת להיות חדשה. הכלי בודק את מסד הנתונים ואת קבצי המקור ואינו דורס נתונים קיימים. כדי להמשיך להשתמש בתיקייה המשוחזרת, הגדירו את `INVOICE_DATA_DIR` בכל הפעלה או העבירו את התיקייה המקורית למקום שמור ואת המשוחזרת ל־`data`, כשהשרת כבוי.

## פיתוח ובדיקות

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.lock
python scripts/setup_ocr.py
python -m playwright install chromium
python -m pytest -q
python run.py
```

בדיקות הדפדפן מרימות שרת ונתונים זמניים, בודקות יבוא, אישור, יצוא/קליטה, פיצול וסימון צ׳ק. אפשר לבחור Chromium קיים באמצעות `INVOICE_BROWSER_EXECUTABLE`. בדיקות OCR אמיתיות דורשות Tesseract ב־PATH.

נתונים נשמרים ב־`data` ואינם נכללים ב־Git. אפשר להגדיר `INVOICE_DATA_DIR` ו־`INVOICE_TESSDATA_DIR`. השרת מאזין רק ל־loopback; אין לפתוח אותו לרשת. המסמכים ומסד הנתונים אינם מוצפנים ביישום, ולכן יש להשתמש בהרשאות Windows וב־BitLocker לפי הצורך.

פרטי שחזור, בחירת מודלים ותוצאות: [דוח אימות](docs/VALIDATION.md). תנאי מודלי Tesseract: [Apache 2.0](third_party/tesseract-models-LICENSE.txt).

מחקר מודלים להורדה, כולל תוצאות CPU בפועל, תמיכה בעברית ומגבלות: [השוואת מודלים](docs/MODEL_RESEARCH.md).

## למידה אישית ואימון מתוך התוכנה

במסך **למידה ואימון אישי** מאשרים כל ספק, שומרים הסברים לתיקונים, משייכים כמה סגנונות כתב ומאמנים מודל ספרות אישי קטן על המעבד. אפשר ללמד אזורי שדות אצל ספק ולייבא רשימת צ׳קים להצלבה. מסך הגרסאות מציג אימון ובדיקה על מסמכים נפרדים, וכולל עצירה, חזרה למנועי הבסיס, יצוא ויבוא של גרסה אישית.

התקנה חדשה מתחילה בלי נתוני לקוחות, דוגמאות או משקולות אישיות. הנתונים האישיים נשמרים במחשב ובנפרד לכל חברה. גיבוי אישי כולל אותם לשחזור שלך; חבילת התקנה כוללת רק קוד ומודלי בסיס ציבוריים. [מדריך הלמידה האישית](docs/PERSONAL_LEARNING.md).

מתוך **זיהוי וחיבורים** ניתן להוריד עם אימות קבצים את מודלי העברית הנוספים ואת מודלי הראייה, ולהפעיל ולעצור מנוע מקומי אחד בכל פעם. האימון האישי פועל גם ללא מודל ראייה גדול.

אפשר לייצא **חבילת למידה** ולייבא אותה למחשב חדש או לעובד אחר בצוות. בוחרים אילו חלקים לשתף, רואים תצוגה מקדימה וממפים ספקים וסגנונות כתב לחברת היעד. כפילויות ותיוגים שונים מוצגים לפני שמירה, ותשובות ספקים מיובאות כהצעות לאישור. החבילה מעבירה ידע וחיתוכים בלי ליצור חשבוניות במחשב המקבל.
